## 1. หลักการ — ไล่สีตามผล ไม่ใช่ตามชื่อ

การไล่สีตาม "ชื่อปุ่ม" จะตันเสมอ เพราะชื่องอกใหม่ได้เรื่อย ๆ และชื่อเดียวกันในแอปนี้ก็หมายคนละเรื่องอยู่แล้ว
(คำว่า "ลบ" มีสามความหมาย · คำว่า "ยกเลิก" มีสองความหมาย)

ทุกปุ่มตอบสามคำถามนี้ได้เสมอ ไม่ว่าจะเป็นปุ่มใหม่แค่ไหน:

1. **กดแล้วย้อนได้ไหม**
2. **คนนอก (ลูกค้า/เว็บสาธารณะ/สรรพากร) เห็นผลหรือยัง**
3. **เปลี่ยนข้อมูลไหม หรือแค่เปิดดู**

สีมาจากคำตอบสามข้อนี้

## 2. สีทั้งหมดมี 5 ระดับ — ไม่เพิ่มสีใหม่

| ชื่อเรียก | `variant` ในโค้ด | สีจริง | ใช้เมื่อ |
|---|---|---|---|
| **น้ำเงินเข้ม** | `secondary` | `#000099` ทึบ ตัวหนังสือขาว | ปล่อยของออกไปถึงคนนอก ย้อนยาก |
| **เทาเข้ม** | `primary` (ค่าเริ่มต้น) | `slate-800` ทึบ ตัวหนังสือขาว | ยืนยันงานที่ยังอยู่ในบ้านเรา ย้อนได้ |
| **ขอบขาว** | `ghost` | พื้นขาว ขอบเทา ตัวหนังสือเทา | ไม่แตะข้อมูลเลย |
| **แดงเงียบ** | `dangerQuiet` | พื้นขาว แดงตอนเอาเมาส์ชี้ | หยุด/ถอย/ยึดคืน แต่กู้ได้ |
| **แดงทึบ** | `danger` | `red-600` ทึบ | กู้ไม่ได้ หรือคนนอกรู้ไปแล้ว |

**กฎบังคับ**

- ปุ่มน้ำเงินเข้ม **ไม่เกิน 1 ปุ่มต่อหนึ่งกล่อง/หนึ่งหน้าจอ** ถ้ามีสองปุ่มแปลว่ายังไม่ได้เลือกว่าอันไหนคือทางหลัก
- ปุ่มแดงทึบ **อยู่ในกล่องยืนยันเท่านั้น ห้ามอยู่ในตาราง** (เหตุผลเดียวกับที่เคยตัดปุ่มแดง 79 ก้อนออกจากตาราง BOQ)
- ปุ่มประจำแถวในตาราง ใช้ได้แค่ **ขอบขาว** กับ **แดงเงียบ**

## 3. พจนานุกรมคำ — หนึ่งความหมาย หนึ่งคำ

| ความหมาย | ใช้คำนี้คำเดียว | เลิกใช้ |
|---|---|---|
| ย้ายเข้าถังขยะ กู้ได้ 30 วัน | **ลบ** | ย้ายไปถังขยะ |
| หายถาวร กู้ไม่ได้ | **ลบถาวร** | "ลบ" เฉย ๆ |
| ปิดไม่ให้ใช้ต่อ — สิ่งของ | **ปิดใช้งาน** | ปิด, เอาออก |
| ปิดบัญชี — คน | **ระงับบัญชี** | ปิดใช้งาน, ปิดบัญชี |
| ซ่อนจากเว็บลูกค้า | **ยกเลิกเผยแพร่** | ซ่อน, เอาออก |
| ถอดออกจากโซนแนะนำหน้าแรก | **เอาออกจากหน้าแรก** | "เอาออก" ลอย ๆ |
| ปิดฟอร์ม/แผงโดยไม่บันทึก | **ยกเลิก** | ปิด, ไม่ยกเลิก |
| ยกเลิกเอกสารที่ออกเลขไปแล้ว | **ยกเลิกใบเสร็จ RC-2026-0001** (มีเลขต่อท้ายเสมอ) | ยืนยันยกเลิก |

**กฎเดียวที่ต้องจำ:** คำที่แปลว่า "ของหาย" ต้องมีวัตถุต่อท้ายเสมอ · คำที่แปลว่า "ไม่ทำอะไร" ห้ามมีวัตถุ

## 5. ข้อที่ขอแย้ง

**"แก้ไข" ไม่ควรเป็นน้ำเงินเข้ม** — ปุ่มแก้ไขในแอปนี้ทุกจุดทำอย่างเดียวคือ *กางฟอร์มออกมา* ยังไม่เปลี่ยน
ข้อมูลสักตัว ปุ่มที่ควรได้สีคือปุ่ม **บันทึก** ที่อยู่ในฟอร์มนั้นต่างหาก

ถ้าให้ "แก้ไข" เป็นน้ำเงินเข้ม จะเกิดสองปัญหาพร้อมกัน: หน้าโครงการหน้าเดียวมีปุ่มแก้ไขหลายจุด
จะกลายเป็นน้ำเงิน 4-5 ก้อนแย่งสายตากันเอง และตาราง 78 แถวที่มีปุ่มแก้ไขประจำแถวจะกลายเป็น
แถบน้ำเงินยาวทั้งคอลัมน์ ซึ่งเป็นอาการเดียวกับปุ่มแดง 79 ก้อนที่เคยตัดออกไป

**กฎที่ใช้แทน:** สีให้ปุ่มที่ *ลงมือทำ* ไม่ใช่ปุ่มที่ *พาไปทำ*

## 6. ตัวขวางในโค้ด ต้องแก้ก่อนไล่สี

`staff-app/src/components/Button.tsx` บรรทัด 36-38

```
primary   → เทา slate-800     ← ชื่อว่า primary แต่ไม่ใช่สีแบรนด์
secondary → นาวี #000099      ← สีแบรนด์จริงซ่อนอยู่ใต้ชื่อ secondary
```

ชื่อกลับด้านกับความรู้สึก คนเขียนปุ่มใหม่พิมพ์ `variant="primary"` หรือไม่ใส่เลยแล้วได้ปุ่มเทา
ตอนนี้มี **53 ปุ่มนั่งอยู่บนค่าเริ่มต้นนี้**

**เสนอเปลี่ยนชื่อ:**

| เดิม | ใหม่ |
|---|---|
| `primary` | `neutral` |
| `secondary` | `brand` |
| `ghost` | `ghost` (คงเดิม) |
| `dangerQuiet` | `dangerQuiet` (คงเดิม) |
| `danger` | `danger` (คงเดิม) |

ไม่เปลี่ยนหน้าตาสักพิกเซล แต่ทำให้กฎบังคับตัวเองได้ เพราะชื่อบอกสีตรง ๆ

## 7. ลำดับงาน

1. **เปลี่ยนชื่อ variant** — ไม่เปลี่ยนหน้าตา ความเสี่ยงต่ำสุด ทำก่อน
2. **แก้ข้อความตามพจนานุกรม (ข้อ 3)** — ไม่แตะตรรกะ ได้ผลกับความเข้าใจมากที่สุด
   เริ่มจาก "ลบ" ของหมวดงาน ซึ่งเป็นจุดที่อันตรายจริงตอนนี้
3. **ไล่สีตามตารางข้อ 4** — ประมาณ 25 จุด
4. **จดกฎลงบันทึกโครงการ** เพื่อไม่ให้ฟีเจอร์หน้าไหลกลับไปแบบเดิม

## 8. สรุปจุดที่ต้องแก้

**เปลี่ยนคำ 8 จุด** — ลบ (หมวดงาน) → ลบถาวร · ลบฉบับร่าง → ลบฉบับร่างถาวร · ย้ายไปถังขยะ → ลบ ·
ยืนยันยกเลิก → ยกเลิกใบเสร็จ RC-xxxx · ไม่ยกเลิก → ยกเลิก · เอาออก → เอาออกจากหน้าแรก ·
ปิด (แผง) → ยกเลิก · ปิดบัญชีพนักงาน → ระงับบัญชี

**เปลี่ยนสี ~25 จุด** — ดูคอลัมน์ ⚠️ ในตารางข้อ 4

**เปลี่ยนชื่อ variant 2 ตัว** — `primary` → `neutral` · `secondary` → `brand`

## 9. ข้อยกเว้นที่ใช้จริงตอนลงมือ (2026-09-24)

ตารางข้อ 4 ชนกับกฎบังคับข้อ 2 ("ปุ่มประจำแถวในตารางใช้ได้แค่ขอบขาวกับแดงเงียบ") อยู่ 4 จุด
เพราะปุ่มที่ควรได้สีทึบดันเป็นปุ่มที่ซ้ำทุกแถว **กฎบังคับชนะ** — สีทึบถูกยกไปไว้ที่ปุ่มยืนยัน
ในกล่อง confirm แทน ปุ่มในแถวเหลือเป็นแบบเงียบ

| จุด | ปุ่มในแถว | ปุ่มยืนยันในกล่อง |
|---|---|---|
| เผยแพร่ (ตารางแบบบ้าน/ผลงาน) | ขอบขาว | — (หน้ารายละเอียดของชิ้นนั้นเป็นนาวีตามตาราง) |
| ลบฉบับร่างถาวร (ตารางใบเสนอราคา) | แดงเงียบ | แดงทึบ |
| ลบถาวร (หมวดงาน) | แดงเงียบ | แดงทึบ |
| ออกใบเสร็จ (แถวรับเงิน) | ลิงก์เงียบ | **นาวี** (เพิ่มกล่องยืนยันใหม่ — เดิมกดแล้วออกเลย) |

**กล่อง confirm ได้คำศัพท์ชุดเดียวกับปุ่ม** — `lib/confirm-context.tsx` เปลี่ยนจาก
`"primary" | "danger"` เป็น `"neutral" | "brand" | "danger"` ให้ตรงกับ `<Button>`

**ที่แก้เพิ่มนอกตาราง** (เจอระหว่างไล่ แล้วผิดกฎข้อ 3 ชัด ๆ)

- `ตั้งลายเซ็น / เปลี่ยนลายเซ็น` · `สำรองตอนนี้` · `ใส่ลงช่องจำนวน` (เครื่องคิดเหล็ก) — นาวี → เทาเข้ม
  ทั้งสามไม่มีใครนอกบริษัทเห็นผล
- `ลบ` ของแบบบ้าน/ผลงานในหน้ารายละเอียด — แดงทึบ → แดงเงียบ (เข้าถังขยะ กู้คืนได้)
- ปุ่มการ์ด "ขั้นตอนถัดไป" ทุกใบที่แค่พาไปหน้าอื่น — เทาเข้ม → ขอบขาว
- คำโปรยหน้าจัดการผู้ใช้ "เปิด/ปิดบัญชีได้" → "ระงับบัญชี และเปิดคืนได้"

**จุดที่ยังทับกันได้** — โครงการที่สถานะ "อนุมัติแล้ว" *และ* มีลูกค้าผูกอยู่ จะเห็นปุ่มนาวีสองปุ่ม
พร้อมกัน (`ออกลิงก์เข้าใช้` ที่หัวการ์ดลูกค้า + `ทำเครื่องหมายส่งมอบงาน` ในการ์ดขั้นตอนถัดไป)
ตอนนี้ยังไม่มีโครงการจริงที่เข้าเงื่อนไขทั้งสองข้อ จึงปล่อยไว้ก่อน
